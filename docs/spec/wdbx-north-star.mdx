**Date:** 2026-06-01
**Status:** **VISION / ROADMAP — not a statement of current capabilities.**
**Scope:** Long-term direction for evolving ABI from a local multi-persona assistant into a WDBX-centered cognitive runtime spanning storage, indexing, compute, security, clustering, and transport.

> **Claims discipline (read first).** This document is aspirational. Every item below is tagged **Current**, **Partial**, or **Proposed**, backed by repo source/tests for the Current/Partial rows. The genuinely **not-repo-proven** items that MUST NOT be presented as existing ABI capabilities in external collateral are: **general native GPU / ANE / TPU execution** (macOS Metal ships optional linked **DOT** behind `abi-gpu` / `metal-kernels` when the backend reports initialized native kernels — not a blanket GPU speedup claim; CUDA/Vulkan kernels and ANE dispatch are not linked; ANE detection + remote-dispatch transport remain the other honest paths), **production multi-host distributed deployment and data sharding** (the consensus RPC is real, supports a shared-secret token and optional peer allowlist, and is loopback/routable-bind tested; no production deployment or sharding is proven), **production-secure / bootstrapped homomorphic encryption** (only a reference-parameter somewhat-homomorphic scheme exists), a **production/learned-SOTA compression codec**, and **any throughput/latency/accuracy figure**. This file is the proposal record the external-claims policy permits; see `docs/contracts/external-claims-audit.mdx` and golden / claim-boundary coverage. When this vision and the source disagree, the source wins (`Cargo.toml`, `crates/`, `tests/golden/`, `./tools/check.sh`).

## 1. Final Mission

Make **WDBX** the shared memory and reasoning substrate for all ABI agents and personas (Abbey, Aviva, Abi): persistent, verifiable, hardware-accelerated, and — over the long horizon — scalable across CPU, GPU, NPU, and TPU environments and multiple nodes. ABI evolves from a single-process assistant into a cognitive runtime where retrieval, persona routing, and integrity are first-class.

```
ABI
 ↓
Persona Router          (Current)
 ↓
WDBX Runtime
 ├─ Storage Layer       (Current — in-process + segment/WAL persistence)
 ├─ Index Layer         (Current — HNSW/SIMD + snapshot-persisted temporal/causal ranker)
 ├─ Compute Layer       (Partial — CPU SIMD via std::simd + optional macOS Metal DOT + CPU fallback + CPU/GPU parity path; ANE detection; TPU remote-dispatch transport)
 ├─ Security Layer      (Partial — SHA-256 chain + snapshot checksum + DGHV add/multiply SHE)
 ├─ Cluster Layer       (Partial — in-process Raft + networked RPC transport over loopback)
 └─ Transport Layer     (Partial — stdio/JSON-RPC + custom one-event MCP loopback HTTP compatibility + REST + cluster/remote-compute RPC)
```

## 3. Layered Architecture

### 3.1 Storage Layer
- **Current:** v2 causal key/value, UUID-addressed vectors, audit DAG blocks, spatial and temporal records, independent per-writer journals/heads, immutable snapshot segments, explicit conflict resolution, non-mutating v1 reads, and verified first-write migration with retained backup. `VersionedStore` backs product callers; v1 snapshot/WAL/segment code remains the compatibility reader and migration oracle.
- **Proposed:** production separate-host coordination, dynamic membership, and sharding. Local multi-process writers are Current; production multi-host is not.
- **Invariants:** committed hash-covered transactions only, causal conflict retention, stable public identity, authenticated-object verification before parse when enabled, and immutable snapshot-backed views.

### 3.2 Index Layer
- **Current:** HNSW graph with SIMD cosine distance and ordered result contracts; **temporal/causal graph + hybrid ranker** (`temporal.rs`): exponential recency decay, causal BFS proximity, and the combined ranking key below (unit-tested and used by MCP `wdbx_query`).
- **Scoring model (implemented in `temporal.rs`, composed with HNSW in `retrieval.rs`, and default for MCP-local `wdbx_query`):**
  ```
  score = semantic × temporal × causal × persona
  ```
  `semantic` comes from HNSW cosine, `temporal` from recency half-life decay, `causal` from causal-edge hop distance, `persona` from the router profile weight. JSONL snapshots persist temporal nodes and causal edges.

### 3.3 Compute Layer
- **Current:** CPU SIMD via Rust `std::simd` (portable SIMD / host-width lanes in `compute.rs`); GPU *capability reporting* plus, on macOS when `metal-kernels` initializes, linked Metal **DOT** behind `crates/abi-gpu/src/metal_kernels.rs` with deterministic CPU fallback otherwise; `compute.rs` dynamic backend selector across CPU (`scalar`/`avx2`/`avx512`/`neon`, host-detected), GPU (`cuda`/`metal`/`vulkan`), NPU (`ane`, with honest `ane_hardware_present()` detection), and TPU (`remote`). `remote_compute.rs` adds a real TCP dispatch transport for the remote-accelerator backend (endpoint-configured, CPU fallback).
- **Proposed:** broader native kernels, CUDA / Vulkan Compute dispatch, and ANE execution. ANE native execution specifically requires Apple CoreML/ObjC (not pure Rust CPU paths) and on-device profiling to verify residency. Selection is already **dynamic** and always degrades to the deterministic CPU path when native kernels are unavailable. HTTP expose decisions: `docs/spec/non-loopback-rest-threat-review.mdx` (proxy TLS preferred; native TLS deferred).

### 3.4 Security Layer
- **Current / locally tested v2 slice:** product callers use v2; audit DAG verification and v1 snapshot/WAL integrity remain tested; opt-in v2 transaction and compacted-segment XChaCha20-Poly1305 encryption and Ed25519 signing use fresh nonces, pre-parse verification, owner-only key files, signature-required verification, and verified/retained generation rekey. `crypto_he.rs` additive homomorphic encryption and `fhe.rs` DGHV **somewhat-homomorphic** encryption remain reference implementations and are **not** security-audited. Plaintext v2 is intentionally readable, so product cutover is not a claim that every store is encrypted.
- **Proposed / remaining:** platform credential-provider adapters and production-secure / bootstrapped full FHE. Do not convert the implemented object slice into AES, RBAC, external-audit, or universal all-data-at-rest claims.

### 3.5 Cluster Layer
- **Current (single-host / controlled routable bind):** `cluster.rs` Raft-style core — leader election, majority-quorum log replication, leader failover, quorum-loss detection (deterministic step model; `abi wdbx cluster demo`) — **and** `cluster_rpc.rs`, a real TCP RequestVote/AppendEntries transport with election/replication/downed-node tests over 127.0.0.1, shared-secret authentication, optional peer allowlisting via `ABI_WDBX_CLUSTER_PEERS`, runtime reload via `ClusterPolicy.withPeers` (loopback-tested; not dynamic membership), and a runnable `abi wdbx cluster serve <port>` node endpoint. Non-loopback binds require `ABI_WDBX_CLUSTER_TOKEN`.
- **Proposed:** production multi-host deployment, TLS/mTLS or equivalent fronting network policy, dynamic membership, and data sharding/partitioning across nodes. Until those are exercised, ABI is **not** a production distributed multi-host system, and sharding is unbuilt. Ops decision record: `docs/spec/cluster-mtls-ops.mdx` (proxy mTLS preferred; native TLS deferred; membership static; sharding Proposed).

### 3.6 Transport Layer
- **Current:** MCP JSON-RPC 2.0 over stdio (64 KB request cap + shared JSON nesting depth bound) plus an automatically attempted custom loopback HTTP compatibility listener (`GET /sse`, `POST /message`) on `127.0.0.1:8080`; bind failure leaves stdio running. `GET /sse` emits one discovery event and closes, so this is not persistent conforming MCP HTTP+SSE. The listener supports optional bearer-token enforcement via `ABI_MCP_HTTP_TOKEN` (fixed-work compare), and incomplete HTTP bodies are rejected (400) rather than dispatched. Durable WDBX open for MCP is **fail-closed** unless `ABI_WDBX_ALLOW_MEMORY_FALLBACK` is set. The **WDBX REST listener** (`rest.rs`) serves `POST /insert /query /verify` and `GET /health /stats` on a loopback port (`abi wdbx api serve [port]`, default 8081), with a unit-tested routing core and optional bearer-token enforcement via `ABI_WDBX_REST_TOKEN` (same incomplete-body + fixed-work bearer behavior).
- **Current (added):** cluster consensus RPC and remote-compute dispatch over TCP (`cluster_rpc.rs`, `remote_compute.rs`), loopback-tested via a shared `net_line` framing helper. Cluster RPC supports `AUTH <token>` RequestVote/AppendEntries frames via `ABI_WDBX_CLUSTER_TOKEN` and optional node-id allowlisting through `ABI_WDBX_CLUSTER_PEERS`.
- **Proposed:** gRPC, WebSocket streaming; hardening the listeners for non-loopback/production use (TLS, authz, rate limiting, origin defense). See `docs/spec/non-loopback-rest-threat-review.mdx` for the claim-honest ops decision record (proxy TLS preferred; native TLS deferred; non-loopback not a supported product mode without explicit threat acceptance).

## 4. API Surface

### Current
The contract-tested public surfaces are the CLI (`crates/abi-cli/src/usage.rs`) and the MCP tool list (`crates/abi-mcp/src/handlers.rs`): `ai_run`, `ai_complete`, `ai_learn`, `ai_train`, `wdbx_query`, `wdbx_stats`, `scheduler_stats`, `scheduler_info`, `connector_test`, `gpu_status`, `plugin_list`, `plugin_run`.

### REST (implemented, loopback — `rest.rs`)
```
POST /insert     POST /query     POST /verify
GET  /health     GET  /stats
```
Served by `abi wdbx api serve [port]` (default 8081). The routing core is a unit-tested `route(method, path, body)` function; `serve` wraps it on a 127.0.0.1 listener. If `ABI_WDBX_REST_TOKEN` is set, the HTTP transport requires `Authorization: Bearer <token>` before routing. Future: gRPC, WebSocket streaming, cluster RPC, and further hardening for non-loopback exposure (TLS, authz, rate limiting, and reviewed deployment topology).

## 5. CLI Surface

**Current frozen top-level commands** (contract-tested, do not break): `help`, `complete`, `train`, `agent`, `backends`, `plugin`, `auth`, `twilio`, `tui`, `dashboard`, `wdbx`, `scheduler`, `nn` (+ the `abi --tui` shortcut).

**`wdbx` command namespace — implemented** (`crates/abi-cli/src/wdbx.rs`, golden / surface coverage under `tests/golden/`):
```
wdbx db init <path>        wdbx db verify <path>        # segment checkpoint + WAL integrity
wdbx db compact <path> [keep]                           # retain newest segment checkpoints
wdbx block insert <path> <profile> <metadata>           # writes segment checkpoint + WAL
wdbx block get <path>
wdbx query <path> [text] [persona] [--limit N] [--json] [--text T] [--persona P]  # stats, or hybrid/persona-scoped semantic search
wdbx benchmark [count]                                  # local in-memory timing with P50/P95/P99
wdbx cluster status                                     # real Raft state-machine status line
wdbx cluster demo [nodes]                               # in-process election/quorum/failover
wdbx cluster serve <port> [node] [host]                 # serve this node's networked consensus RPC; non-loopback requires ABI_WDBX_CLUSTER_TOKEN
wdbx compute info                                       # CPU/GPU/NPU/TPU backends + ANE detection + remote endpoint
wdbx secure demo                                        # int8 + Huffman + demo rANS/order-1 + autoencoder; additive HE + DGHV SHE
wdbx gpu info                                           # GPU backend capabilities
wdbx api serve [port]                                   # loopback REST listener (default 8081)
```
`cluster status` reports the real in-process Raft state-machine status line; `cluster demo` runs the consensus core and `cluster serve` exposes its networked RequestVote/AppendEntries transport over loopback or a controlled routable bind (§3.5). The routable path requires `ABI_WDBX_CLUSTER_TOKEN` and can enforce `ABI_WDBX_CLUSTER_PEERS`, but it is still not a production deployment claim. `api serve` starts the loopback REST listener implemented in `rest.rs` (`POST /insert /query /verify`, `GET /health /stats`; §3.6/§4). **CUDA/Vulkan/ANE native dispatch, broader GPU kernels beyond optional Metal DOT, production multi-host distributed deployment + sharding, a production/SOTA learned compression codec, and production-secure/bootstrapped FHE remain Proposed** (§2).

## 8. Phased Roadmap

| Phase | Theme | Gate |
| --- | --- | --- |
| **1** | Single-node cognitive runtime: durable storage (WAL + segments + recovery), persona-weighted scoring, always-on persistence, REST `/insert /query /verify`. | **Landed for single-node/MCP** — WAL + replay/corruption recovery, segment checkpoints as the default runtime checkpoint source, epoch reclamation, runtime CLI auto-recovery, snapshot-persisted temporal/causal records, MCP default hybrid ranking, the `wdbx` CLI, and the loopback REST listener are landed and tested. |
| **2** | Multi-node cluster: membership, replication, leader failover, cluster RPC. | First **Proposed** layer; gate on real tests before any "distributed" claim. |
| **3** | Neural compression of stored embeddings/state. | Requires measured compression artifact before claiming ratios. |
| **4** | Homomorphic encryption for query-over-encrypted-memory. | Research horizon; claim only with a working, tested path. |
| **5** | Self-optimizing planner (adaptive backend + index selection). | Builds on dynamic backend selection + scheduler/metrics. |
| **6** | Autonomous cognitive fabric: agents + personas operate over WDBX as shared substrate across hardware tiers. | Culmination; depends on all prior phases. |

**Near-term execution order after Phase 1:** keep broader CLI semantic retrieval UX and future transport/compute/security layers behind the existing contract discipline. Each step keeps plugin mod/stub parity and passes `./tools/check.sh` before it is marked done in `tasks/todo.md`.
