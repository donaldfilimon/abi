**Date:** 2026-06-01
**Status:** **VISION / ROADMAP — not a statement of current capabilities.**
**Scope:** Long-term direction for evolving ABI from a local multi-persona assistant into a WDBX-centered cognitive runtime spanning storage, indexing, compute, security, clustering, and transport.

> **Claims discipline (read first).** This document is aspirational. Every item below is tagged **Current**, **Partial**, or **Proposed**, backed by repo source/tests for the Current/Partial rows. Current local evidence includes exact v2 committed-transaction replication, persisted deterministic PQ/autoencoder artifacts, optional TFHE-rs demo execution, locally verified Metal numerical paths, a single-host multi-process cluster demo, and an authenticated bounded gRPC/WebSocket gateway with local plaintext/TLS/mTLS runtime tests. It does **not** prove Metal speedups, CoreML/ANE residency (only the compute-unit request), CUDA/Vulkan runtime execution, production multi-host deployment/sharding, production-secure or independently audited FHE, SOTA learned compression, hosted/Windows behavior, DAST, or throughput/latency/accuracy figures. Source wins (`Cargo.toml`, `crates/`, tests, `./tools/check.sh`).

## 1. Final Mission

Make **WDBX** the shared memory and reasoning substrate for all ABI agents and personas (Abbey, Aviva, Abi): persistent, verifiable, hardware-accelerated, and — over the long horizon — scalable across CPU, GPU, NPU, and TPU environments and multiple nodes. ABI evolves from a single-process assistant into a cognitive runtime where retrieval, persona routing, and integrity are first-class.

```
ABI
 ↓
Persona Router          (Current)
 ↓
WDBX Runtime
 ├─ Storage Layer       (Current — in-process + segment/WAL persistence)
 ├─ Index Layer         (Current — HNSW/SIMD + snapshot-persisted temporal/causal ranker)
 ├─ Compute Layer       (Partial — abi-compute contracts + CPU SIMD + scoped Metal runtime + CPU oracle; CoreML request only)
 ├─ Security Layer      (Partial — authenticated v2 + reference DGHV/TFHE demos)
 ├─ Cluster Layer       (Partial — exact single-host replication/repair/rebalance + authenticated RPC)
 └─ Transport Layer     (Partial — stdio/JSON-RPC + custom one-event MCP loopback HTTP compatibility + REST + cluster/remote-compute RPC)
```

## 3. Layered Architecture

### 3.1 Storage Layer
- **Current:** v2 causal key/value, UUID-addressed vectors, audit DAG blocks, spatial and temporal records, independent per-writer journals/heads, immutable snapshot segments, explicit conflict resolution, non-mutating v1 reads, and verified first-write migration with retained backup. `VersionedStore` backs product callers; v1 snapshot/WAL/segment code remains the compatibility reader and migration oracle.
- **Proposed:** production separate-host coordination, dynamic membership, and sharding. Local multi-process writers are Current; production multi-host is not.
- **Invariants:** committed hash-covered transactions only, causal conflict retention, stable public identity, authenticated-object verification before parse when enabled, and immutable snapshot-backed views.

### 3.2 Index Layer
- **Current:** HNSW graph with SIMD cosine distance and ordered result contracts; **temporal/causal graph + hybrid ranker** (`temporal.rs`): exponential recency decay, causal BFS proximity, and the combined ranking key below (unit-tested and used by MCP `wdbx_query`).
- **Scoring model (implemented in `temporal.rs`, composed with HNSW in `retrieval.rs`, and default for MCP-local `wdbx_query`):**
  ```
  score = semantic × temporal × causal × persona
  ```
  `semantic` comes from HNSW cosine, `temporal` from recency half-life decay, `causal` from causal-edge hop distance, `persona` from the router profile weight. JSONL snapshots persist temporal nodes and causal edges.

### 3.3 Compute Layer
- **Current:** cycle-free `abi-compute` contracts, deterministic CPU SIMD/top-k, evidence-gated accelerator execution, and WDBX v2 batch-search integration. The macOS Metal adapter can execute dot/cosine/norm/batch-cosine and becomes runtime-verified only after CPU-oracle parity; fallback stays deterministic.
- **Partial / proposed:** CoreML proves a `.cpuAndNeuralEngine` request only. CUDA/Vulkan adapters report compile/tool state but no runtime execution. ANE residency, production remote compute, broader runtime proof, and performance claims require fresh execution/profiling evidence.

### 3.4 Security Layer
- **Current / locally tested v2 slice:** product callers use v2; opt-in XChaCha20-Poly1305 and Ed25519 protect independently authenticated transaction/segment objects with pre-parse verification, owner-only key files, signature-required verification, rekey, and confirmation-gated GC. Plaintext v2 remains supported. DGHV refresh is secret-key-assisted education; the optional TFHE-rs demo is dependency execution, not ABI-authored or audited production cryptography.
- **Current provider evidence:** the object-safe credential-provider surface reports the existing macOS Keychain and Windows owner-protected-file adapters without changing their default behavior. Linux Secret Service is an explicit unavailable stub, and no live macOS round-trip or Windows/Linux runtime proof was produced by this wave.
- **Proposed / remaining:** Linux Secret Service implementation, live cross-platform provider proof, independent cryptographic review, protective-use approval, and production parameters/operations. Do not infer Windows Credential Manager/DPAPI, AES, RBAC, universal encryption, or an ABI-authored bootstrapped FHE system.

### 3.5 Cluster Layer
- **Current (single-host):** the Raft-style core and authenticated TCP RPC remain, joined by signed membership, rendezvous placement, exact encoded-transaction quorum replication, conflict-preserving read repair, stable search fan-out, and hash-verified resumable rebalance. `cluster local-demo` launches 3–9 authenticated local processes and can emit JSON evidence.
- **Proposed:** production separate-host deployment, hosted/Windows execution proof, reviewed TLS/mTLS topology for the cluster path, and production operations. The implemented shard placement/replica APIs are local exact-behavior evidence, not a claim that ABI is a production distributed database.

### 3.6 Transport Layer
- **Current:** MCP JSON-RPC 2.0 over stdio (64 KB request cap + shared JSON nesting depth bound) plus an automatically attempted custom loopback HTTP compatibility listener (`GET /sse`, `POST /message`) on `127.0.0.1:8080`; bind failure leaves stdio running. `GET /sse` emits one discovery event and closes, so this is not persistent conforming MCP HTTP+SSE. The listener supports optional bearer-token enforcement via `ABI_MCP_HTTP_TOKEN` (fixed-work compare), and incomplete HTTP bodies are rejected (400) rather than dispatched. Durable WDBX open for MCP is **fail-closed** unless `ABI_WDBX_ALLOW_MEMORY_FALLBACK` is set. The **WDBX REST listener** (`rest.rs`) serves `POST /insert /query /verify` and `GET /health /stats` on a loopback port (`abi wdbx api serve [port]`, default 8081), with a unit-tested routing core and optional bearer-token enforcement via `ABI_WDBX_REST_TOKEN` (same incomplete-body + fixed-work bearer behavior).
- **Current (added):** cluster consensus RPC and remote-compute dispatch over TCP (`cluster_rpc.rs`, `remote_compute.rs`), loopback-tested via a shared `net_line` framing helper. Cluster RPC supports `AUTH <token>` RequestVote/AppendEntries frames via `ABI_WDBX_CLUSTER_TOKEN` and optional node-id allowlisting through `ABI_WDBX_CLUSTER_PEERS`.
- **Current (local gateway):** `abi-wdbx-gateway` exposes all eight bounded bearer-authenticated gRPC methods and metadata-only WebSocket mutation/query events on two explicit listeners. Loopback is the default; any non-loopback listener requires owner-protected bearer credentials plus TLS, and an optional client CA makes mTLS mandatory. Local tests cover plaintext and TLS/mTLS handshakes, missing-client-certificate refusal, failed-auth/upgrade rate limits, request/frame/value/vector/batch/stream/idle limits, exact Origin policy, slow consumers, and bounded teardown. `MembershipChange` is gateway-local nondurable reference state, not signed cluster membership. Hosted production deployment, separate-host operations, certificate rotation, DAST, and external review remain unproven.

## 4. API Surface

### Current
The contract-tested public surfaces are the CLI (`crates/abi-cli/src/usage.rs`) and the MCP tool list (`crates/abi-mcp/src/handlers.rs`): `ai_run`, `ai_complete`, `ai_learn`, `ai_train`, `wdbx_query`, `wdbx_stats`, `scheduler_stats`, `scheduler_info`, `connector_test`, `gpu_status`, `plugin_list`, `plugin_run`.

### REST (implemented, loopback — `rest.rs`)
```
POST /insert     POST /query     POST /verify
GET  /health     GET  /stats
```
Served by `abi wdbx api serve [port]` (default 8081). The routing core is a unit-tested `route(method, path, body)` function; `serve` wraps it on a 127.0.0.1 listener. If `ABI_WDBX_REST_TOKEN` is set, the HTTP transport requires `Authorization: Bearer <token>` before routing. Future: gRPC, WebSocket streaming, cluster RPC, and further hardening for non-loopback exposure (TLS, authz, rate limiting, and reviewed deployment topology).

## 5. CLI Surface

**Current frozen top-level commands** (contract-tested, do not break): `help`, `complete`, `train`, `agent`, `backends`, `plugin`, `auth`, `twilio`, `tui`, `dashboard`, `wdbx`, `scheduler`, `nn` (+ the `abi --tui` shortcut).

**`wdbx` command namespace — implemented** (`crates/abi-cli/src/wdbx/`, golden / surface coverage under `tests/golden/`):
```
wdbx db init <path>        wdbx db verify <path>        # segment checkpoint + WAL integrity
wdbx db compact <path> [--codec none|pq|autoencoder]    # publish a verified immutable v2 generation; learned codecs are explicitly lossy
wdbx block insert <path> <profile> <metadata>           # writes segment checkpoint + WAL
wdbx block get <path>
wdbx query <path> [text] [persona] [--limit N] [--json] [--text T] [--persona P]  # stats, or hybrid/persona-scoped semantic search
wdbx benchmark [count]                                  # local in-memory timing with P50/P95/P99
wdbx cluster status                                     # real Raft state-machine status line
wdbx cluster demo [nodes]                               # in-process election/quorum/failover
wdbx cluster local-demo [nodes] [--json]                # authenticated 3..=9 process single-host exact replication/repair/rebalance proof
wdbx cluster serve <port> [node] [host]                 # serve this node's networked consensus RPC; non-loopback requires ABI_WDBX_CLUSTER_TOKEN
wdbx compute info                                       # CPU/GPU/NPU/TPU backends + ANE detection + remote endpoint
wdbx secure demo                                        # compression + additive HE + bounded-depth DGHV reference demo
wdbx secure dghv-bootstrap                             # feature-gated secret-key-assisted educational refresh
wdbx secure tfhe                                       # feature-gated pinned TFHE-rs demo; no independent ABI audit
wdbx gpu info                                           # GPU backend capabilities
wdbx api serve [port]                                   # loopback REST listener (default 8081)
```
`cluster local-demo` is single-host multi-process evidence; it is not a real multi-host or production deployment claim. `secure dghv-bootstrap` is not cryptographic bootstrapping, and `secure tfhe` proves only the optional pinned dependency demo without independent ABI audit. CUDA/Vulkan runtime execution, ANE residency, production multi-host deployment, SOTA compression, and production cryptography remain unproven.

## 8. Phased Roadmap

| Phase | Theme | Gate |
| --- | --- | --- |
| **1** | Single-node cognitive runtime: durable storage (WAL + segments + recovery), persona-weighted scoring, always-on persistence, REST `/insert /query /verify`. | **Landed for single-node/MCP** — WAL + replay/corruption recovery, segment checkpoints as the default runtime checkpoint source, epoch reclamation, runtime CLI auto-recovery, snapshot-persisted temporal/causal records, MCP default hybrid ranking, the `wdbx` CLI, and the loopback REST listener are landed and tested. |
| **2** | Multi-node cluster: membership, replication, leader failover, cluster RPC. | Local exact-behavior slice landed; production separate-host deployment remains Proposed. |
| **3** | Neural compression of stored embeddings/state. | Deterministic persisted artifacts landed; SOTA/production ratios require reproducible benchmark evidence. |
| **4** | Homomorphic encryption for query-over-encrypted-memory. | Reference/optional dependency demos landed; audited production use remains a research horizon. |
| **5** | Self-optimizing planner (adaptive backend + index selection). | Builds on dynamic backend selection + scheduler/metrics. |
| **6** | Autonomous cognitive fabric: agents + personas operate over WDBX as shared substrate across hardware tiers. | Culmination; depends on all prior phases. |

**Near-term execution order after Phase 1:** keep broader CLI semantic retrieval UX and future transport/compute/security layers behind the existing contract discipline. Each step keeps plugin mod/stub parity and passes `./tools/check.sh` before it is marked done in `tasks/todo.md`.
